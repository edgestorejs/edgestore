## Ask your agent to debug it

Copy this prompt into your coding agent and describe what is going wrong:

```text
Help me debug this EdgeStore issue: [describe the problem].

Read https://edgestore.dev/docs/troubleshooting.md and inspect my existing
integration. Explain the cause before making changes.
```

Include the error message and steps to reproduce it, without credentials or
private file URLs. The checks below work with or without an agent.

## Route not found or method not allowed

Open the handler's health endpoint. With the default Next.js route it is
[http://localhost:3000/api/edgestore/health](http://localhost:3000/api/edgestore/health).
Use your backend origin and mounted path for other adapters.

An `OK` response confirms that this route is reachable, not that credentials,
bucket access, or uploads work. For a 404 or 405, check the catch-all route and
GET/POST exports for your installed framework version. Match the React provider's
`basePath` to the mounted endpoint, including any proxy prefix.

## Credentials or access denied

Confirm the backend loads the expected env file before creating the storage
provider. Check variable presence without logging values. Keep server keys out of
frontend variables and verify that the configured provider and project match the
intended account. Reuse valid credentials instead of creating a new project or key
as a first troubleshooting step.

For protected buckets, check the application's authentication context and access
rules. A signed-in MCP client does not authenticate a user of your application.
Do not make a bucket public to bypass an authorization failure.

## Browser upload failures

Check the browser console for errors and the failing request and response in the
Network panel, then use
[Error handling](/docs/error-handling) to identify validation, size, or access
errors. Confirm that the React provider wraps the upload component.

For separate frontend and backend origins, allow the intended frontend origin in
CORS and check the adapter's cookie and deployment requirements. Do not combine
arbitrary reflected origins with credentials. Preserve type-only router imports
so backend code and credentials cannot enter the frontend bundle.

After a fix, upload through the application and retrieve the file independently.
For protected files, confirm that unauthorized retrieval is denied too.

## Enable server debug logging

Enable [debug logging](/docs/logging) temporarily to inspect server-side failures.
These messages appear in your backend's terminal or server logs, not the browser
console. Redact keys, tokens, cookies, and signed URLs before sharing logs or
screenshots.

## Inspect the application with the CLI

If the CLI is available:

```sh
edgestore --cwd <app> agent context --json
edgestore --cwd <app> doctor --offline --json
```

Use the backend directory for server checks in a split workspace. `agent context`
reports installed versions and local references. `doctor --offline` inspects
configuration without authenticating or running the application. Follow its
suggestions, but investigate warnings and skipped checks; a passing check is not
an end-to-end upload test.

If `agent context` lists candidate workspaces and exits with code 2, select the
application with `--cwd`. Do not install packages at the monorepo root to resolve
that message. If a separate CLI is too old to provide these commands, inspect the
app's installed packages and configuration directly.

## MCP setup or sign-in failures

MCP manages remote resources separately from your application's upload route.
Reconnecting it does not repair that route or load backend environment variables.

Use `edgestore mcp status --client codex` (or `claude` / `cursor`) to inspect saved
configuration. It does not test OAuth or connectivity. Follow the client-specific
[sign-in instructions](/docs/agents#sign-in), then try a read such as listing
projects. Review granted permissions if one action works but another is denied.

## Try an example app

Run an [example close to your framework](https://github.com/edgestorejs/edgestore/tree/main/examples)
to compare with your application.

For Next.js:

```sh
npx degit edgestorejs/edgestore/examples/next-basic#main edgestore-example
cd edgestore-example
npm install
```

Add your EdgeStore keys to `.env.local` as shown in
[Quick start](/docs/quick-start#environment-variables), then run:

```sh
npm run dev
```

Open the URL printed in the terminal and try an upload.

## Still blocked?

Ask in [Discord](https://discord.gg/HvrnhRTfgQ) or
[open an issue](https://github.com/edgestorejs/edgestore/issues) with your framework,
installed EdgeStore versions, failing operation, and a redacted error. Never
include credentials or private file URLs.

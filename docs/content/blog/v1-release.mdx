## REST API and standalone SDK

EdgeStore's new v2 API allows you to do most of the things you can do through the dashboard. Allowing you to create automations and more importantly, giving a good foundation to the other tools, which are super important for this new era of agentic development.

```ts
import { createEdgeStoreSdk } from '@edgestore/sdk';

const sdk = createEdgeStoreSdk({
  credentials: {
    token: process.env.EDGESTORE_MANAGEMENT_TOKEN!,
  },
});

const { project } = await sdk.management.projects.create({
  account: process.env.EDGESTORE_ACCOUNT_ID!,
  name: 'My new app',
});

console.log(project.id);
```

The API is divided in 2 parts, the `runtime` and the `management`.

- `runtime`
  - Works with the keys already configured in your app, scoped to their project
  - Can be used for actions like managing files, listing buckets, and generating signed URLs.
- `management`
  - Needs a user or account level management token
  - Can be used for actions that could only be done through the dashboard. Like managing projects, buckets, keys, members, and more, within the token's permissions.

Keep project secrets and management tokens on the server.

See the [SDK guide](/docs/sdk) for more.

## Improved access control (private files)

There were 2 main improvements to protected files access control on EdgeStore.

The first one was on the cookie based access control, where originally it wouldn't work on browsers that blocked third party cookies by default. Now with the implementation of [partitioned cookies (CHIPS)](https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Third-party_cookies/Partitioned_cookies) we can work around this issue in browsers that support partitioned cookies.

The other improvement was on implementing signed urls. Now apps can add their own custom logic to give access to a file.

The access control configuration is recommended when all the information needed to give access is in the user's context and the file path. The access control check on the file origin doesn't need any DB queries so it is very performant.

Signed urls are recommended when you need a more dynamic or custom logic that needs access from your DB to decide if the user can access the file or not. Check permissions in your backend before generating a signed URL. Anyone with the link can use it until it expires.

See the [access control configuration](/docs/configuration#access-control-experimental) and [signed URL guide](/docs/backend-client#private-read-urls) for more.

## Expanded external provider support

In case you didn't know, the EdgeStore package can also be used with your own storage provider like S3 compatible providers or Azure.

On this new version the support was greatly improved. Now you can also use the [backend client](/docs/backend-client) for external providers and more features like multipart uploads for S3 and block uploads for Azure were also added for large files.

Examples on how to connect to other S3 compatible providers like Cloudflare R2, Backblaze B2, DigitalOcean Spaces, Google Cloud Storage, Tigris, Supabase Storage, and MinIO were also added to the docs.

See the [S3-compatible services guide](/docs/providers/s3#s3-compatible-services) and [Azure guide](/docs/providers/azure-blob) for setup and provider differences.

## Standard schema support

Until now we had to use zod for the bucket input schemas. Now we can use any Standard Schema compatible object schema like Zod, Valibot and ArkType.

See the [input schema configuration](/docs/configuration#metadata--file-path) for more.

## Other improvements

The cookie initialization only runs when needed for access control, reducing http request for apps that don't use it.

Batch methods were added to the client side and backend clients.

- [Client side](/docs/quick-start#delete-file): `deleteMany` and [`confirmMany`](/docs/quick-start#temporary-files).
- [Backend client](/docs/backend-client): `deleteMany`, `confirmMany`, `restoreMany`, and `createSignedUrls`, where supported by the provider.

Emptying a bucket now runs asynchronously on the background, making it more reliable for large buckets and allowing you to see the progress while the files are being deleted.

[Upload transforms](/docs/quick-start#transform-files-before-upload) let you resize or convert files before uploading them. They also work in [backend uploads](/docs/backend-client#transform-a-file-before-upload). Signed URLs, transforms, and the initialization improvement first shipped in v0.8 and carry forward into v1.

And other improvements you can check from the [full changelog](https://github.com/edgestorejs/edgestore/releases).
